# Money Forward 連携 — 手順書

> 予実管理システム（finance.biglight.jp）と **MF クラウド請求書 / MF クラウド会計** をつなぐ方法。
> 作成 2026-09-18。設計の考え方は `THIET-KE-YOJITSU.md` §4.2b、規則の実物は `backend/src/mfsync.ts`。

---

## 0. いちばん大事なこと

| | |
|---|---|
| **読むだけです** | この システムから MF へは **1バイトも書きません**。請求書の作成・修正・送付・入金ステータスの変更、仕訳の登録はしません。OAuth のトークン取得だけが例外です。 |
| **仕訳は経理（会計事務所）** | この システムは「いくら請求し・いくら入り・いくら残っているか」を持つだけ。仕訳は **消込一覧 CSV** を渡して、経理が MF 会計で入れます。 |
| **API が無くても回ります** | すべての取り込みに **CSV の道**があります。API と CSV は同じ規則（`mfsync.ts`）を通るので、結果は同じです。 |
| **同じものは二度入りません** | 請求書は MF の `id`、入金は取引 `id`（CSV は 日付+金額+名義）で見分けます。何度流しても増えません。 |
| **締めた期は動きません** | 締めた期（設定 › 基本設定 の 期の締め）は、自動同期でも人の操作でも変わりません。 |

## 1. 毎日の流れ

```
毎日 06:00（自動・日本時間／時刻と ON/OFF は 設定 › API・AI連携 ›「設定を変える」）
  MF 請求書 ──▶ 請求（未確認 / 自動確定）      … 回収 › 請求の確認
  銀行の入出金明細 ──▶ 入金                      … 回収 › 入金
  自動消込（一致 / 手数料差引 / まとめ払い）
      ↓ 人がやること
  ・請求の確認：未確認 の請求を見て「確定」
  ・入金：消し込めなかったものだけ手当て（振込名義の対応づけ・部分入金）
      ↓ 月次
  ・回収 › 突合：MF 会計の試算表を取り込み、売掛残高と突き合わせる → 合ったら 設定 › 基本設定 でその期を締める
  ・入金 › 消込一覧CSV → 経理へ渡す（経理が MF 会計で仕訳）
```

## 2. API を使う

### 2.1 使っているもの（2026-09-18 に公式ドキュメントで確認）

| | 値 | 出典 |
|---|---|---|
| 認可 | `GET https://api.biz.moneyforward.com/authorize` | 開発者サイト「アクセストークンを取得する」 |
| トークン | `POST https://api.biz.moneyforward.com/token`（更新も同じ） | 同上 |
| クライアント認証 | **CLIENT_SECRET_BASIC**（`Authorization: Basic base64(ClientID:ClientSecret)`）。推奨方式 | 開発者サイト「アプリポータルの概要（OAuth）」 |
| スコープ | **`mfc/invoice/data.read`**（読み取りのみ。書き込み `…data.write` は要求しません） | クラウド請求書サポート「請求書APIについて」 |
| 請求書 API | `GET https://invoice.moneyforward.com/api/v3/billings`（`page` / `per_page`≤100 / `range_key` / `from` / `to` / `status`） | クラウド請求書 API v3 ドキュメント |
| エラー | `{ "errors": [{ "code": …, "message": … }] }` ・ **429 = レート制限** | 開発者サイト「API共通仕様」 |
| 有効期限 | トークンの `expires_in` をそのまま使い、**切れる1分前に `refresh_token` で自動更新** | 公開ドキュメントに固定値の記載なし → レスポンスに従う |

アプリ登録（MF アプリポータル）で必要なのは この2つだけです:
リダイレクト URI `https://finance.biglight.jp/api/mf/callback` ／ スコープ `mfc/invoice/data.read`。

### 2.2 鍵を入れる（どちらか一方）

**① 画面から貼るだけ（おすすめ・SSH 不要）**

設定 › API・AI連携 › Money Forward 連携 › **［鍵を入れる］**（管理者のみ）
→ ClientID と ClientSecret を貼り付け → 保存 → そのまま［接続する］。

- 入れた鍵はサーバーの DB（`server_config.mf_client`）に入ります。**画面・API の返り・ログ・Git には二度と出ません**
  （状態表示は「鍵あり・先頭4文字・文字数」だけ）。
- 鍵を別のアプリのものに入れ替えると、前の接続（トークン）は自動で切れます（別アプリのトークンを使い回さないため）。
- 消すときは同じ場所の「鍵を消す」。
- **`.env` に鍵が入っている場合は `.env` が優先**され、画面からは変更できません（サーバーの設定を正とするため）。

**② サーバーの `.env` に入れる（VPS で1回）

ClientSecret を**どこにも貼らずに**入れるためのスクリプトを用意しています。VPS で:

```bash
cd "$(docker inspect yojitsu-web --format '{{index .Config.Labels "com.docker.compose.project.working_dir"}}')" \
  && bash vps/enable-mf.sh
```

（`.env` を使う運用のとき）ClientID は表示入力、**ClientSecret は伏字入力**。`.env` に書いて（600 権限・バックアップ付き）api コンテナを作り直し、
最後に自己診断まで流します。やめるときは `bash vps/enable-mf.sh off`。

> `env_file` はコンテナを**作るとき**にしか読まれません。`restart` では反映されないので、スクリプトは
> `docker compose up -d --force-recreate api` を使います。

会計（入出金明細・試算表）も API から取る場合だけ、`.env` に `MF_ACCOUNTING_ENABLED=true` を足します
（未設定でも CSV で運用できます）。

### 2.3 つなぐ（画面で1回）

**設定 › API・AI連携** の「Money Forward 連携」で **接続する**（管理者のみ）→ MF の画面で許可 → 戻ってきたら「接続中」。
トークンはサーバーの DB（`server_config`）に入ります。画面・API の返り・ログ・Git には出しません（`scrub()` で必ず消します）。

### 2.4 本番で確かめる（読むだけ）

```bash
docker compose exec api node dist/mfcheck.js            # 設定・接続・請求書の取得・取り込み計画（書かない）
docker compose exec api node dist/mfcheck.js --refresh  # リフレッシュトークンも試す
docker compose exec api node dist/mfcheck.js --days 90  # 期間を変える（既定 60日）
docker compose exec api node dist/mfcheck.js --apply    # 実際に取り込み、もう一度流して「重複0」を確かめる
```

トークンは**先頭4文字と長さ**だけ出ます。中身は出しません。

## 3. CSV で取り込む（API を使わない道）

| 取り込むもの | 画面 | 出どころ | 必要な列（見出しで判断・順番自由） |
|---|---|---|---|
| 請求 | 回収 › 請求の確認 →「請求を取り込む」 | MF 請求書の一覧 CSV | 取引先名・請求日・合計金額（あれば ID・請求書番号・売上計上日・お支払期限・小計・ステータス） |
| 入金 | 回収 › 入金 →「入金を取り込む」 | MF 会計の入出金明細、または銀行の CSV | 日付・入金金額（あれば ID・内容／摘要） |
| 試算表 | 回収 › 突合 →「試算表を取り込む」 | MF 会計の試算表（貸借対照表） | 勘定科目・残高（あれば 勘定科目コード） |

- Shift_JIS のファイルも読めます。
- 読み込むと、まず **取り込む前の内容（新規 / 更新 / 変更なし / 下書き除外 / 締め済みで見送り）** が出ます。確認してから取り込みます。
- 下書き（ステータスが 下書き）の請求は入りません。

## 4. 決めごと（なぜそうしているか）

- **請求の鍵は MF の `id`**。請求書番号は MF 側で重複することがあるため鍵にしません。
- **確定（`confirmStatus`）**
  - 取引先が当たり、請求ルールと金額が合う（またはルールが無い）→ **自動で確定**
  - それ以外 → **未確認**。人が「請求の確認」で確定します。
  - 確定済みの請求を MF 側で直した場合、**この システムの数字は変えません**。`mfDiff` に差を残し、「MF差異」として出します。どちらに合わせるかは人が決めます。
- **取引先の対応づけ**：`companies.mfPartnerId` → 名前（株式会社・㈱・空白を無視）→ 人が選ぶ。選んだ対応は覚えます。
- **入金の振込名義**：`companies.bankPayerNames[]` に覚えます。最初は「取引先を決める」で1回選ぶだけです。
- **自動消込**：確定済み・残高あり・期日が入金日の −45日〜+15日 の請求だけを相手にします。
  ① ぴったり1件 → 消込 ② 1件・550/660/880円 などの不足 → 手数料として消込 ③ 同じ会社の複数（最大4件）の合計が一致 → まとめて消込 ④ それ以外 → **消し込まず「要確認」**（当てずっぽうで消さない）。
- **試算表は実績を上書きしません**。予実の実績は今までどおり伝票から計算します。試算表は突合のための外の数字として `trialBalance` に別置きします。
- **請求書はこの システムでは作りません**。請求ルールは「今月ぶんが MF から入っているか」を見張るだけ（請求の確認 › 請求もれチェック）。

## 5. 手で動かす

| したいこと | 場所 |
|---|---|
| 今すぐ全部同期（請求 → 入金 → 自動消込） | 設定 › API・AI連携 ›「今すぐ同期」 |
| 請求だけ取り込む | 回収 › 請求の確認 ›「請求を取り込む」 |
| 入金だけ取り込む | 回収 › 入金 ›「入金を取り込む」 |
| 自動消込だけ流す | 回収 › 入金 ›「自動で消し込む」 |
| 経理へ渡す CSV | 回収 › 入金 › ツール ›「消込一覧CSV」 |
| 期を締める | 設定 › 基本設定（差が 0 になってから） |

外部システム・AI から読むときは API v1 にも口があります（鍵が必要・読み取り専用）:
`GET /api/v1/reports/settlement?month=YYYY-MM` / `GET /api/v1/reports/reconciliation?month=YYYY-MM`

## 6. 困ったとき

| 症状 | 見るところ |
|---|---|
| 「接続されていません」 | 設定 › API・AI連携 で接続。`.env` に鍵が無ければ CSV で運用できます |
| 前回のエラーが出ている | 同じ画面に理由が出ます。トークン切れなら「接続する」をもう一度 |
| 銀行の明細が入ってこない | ダッシュボードに「入出金明細が止まっています」と出ます。MF 側の銀行連携をご確認ください |
| 請求が二重に見える | 「請求の確認」で、この システムで手入力した分と MF 分が重なっていないか確認（取り込み時にも警告が出ます） |
| 締めた期を直したい | 設定 › 基本設定 で その期の締めを外す（管理者のみ・監査ログに残ります） |
