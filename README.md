# BIGLIGHT 予実管理システム

社内の**お金**を1か所で見るための業務システム。柱は4つです。

1. **回収（売掛金）** — 請求して、入金を消し込み、遅れている会社を追う ← いちばん大事
2. **支払（買掛金）** — 払うべきものを期日で管理する
3. **予実管理** — 予算と実績、着地見込み
4. **払うお金の中身** — 勘定科目（大・中・小）と **建物ごと**の費用

> 人（特定技能者）の管理は CRM が正です。このシステムは **お金だけ**を見ます。

- 会計年度：**8月1日 〜 翌年7月31日**（Q1=8〜10月）
- 公開先：https://finance.biglight.jp
- 設計思想と作り方：[`CONG-THUC-XAY-DUNG-APP.md`](CONG-THUC-XAY-DUNG-APP.md)（BIGLIGHT共通の作法）
- データ設計：[`THIET-KE-YOJITSU.md`](THIET-KE-YOJITSU.md)

## 使いはじめる順番

1. **CRM連携** — 所属機関・特定技能者・在籍期間を取り込む（[手順](crm-integration/README.md)）
   API未設定でも **CSV取り込み** で始められます。
2. **取引先管理** — 会社ごとに
   - 締日・支払サイト・支払日（→ 入金期日が自動で決まる）
   - **請求ルール**（人数×単価／月額固定／都度）
   CRMに無い会社（仕入先・外部取引先）はここで直接追加します。
3. **請求管理 › 請求を作成（月まとめ）** — 在籍者数から請求書を自動生成 → 内容を確認 → 確定
4. **予実管理 › 予算・見込の入力** — 年間予算を入力（前年実績×○%からの作成も可）
5. **費用管理 › ＋費目を追加** — 毎月かかるもの（家賃・給与・通信・リース…）を登録し、月額予定を入れる
   - **支払先**を選びます（一覧に無ければフォームの中から新しい取引先を作れます）
   - **払い方**を決めます … 即払い＝毎月マスに打つ／**買掛**＝毎月の支払請求を作り、期日と残高で管理
   → 「定期費用を反映」で12か月ぶんを一気に埋め、以後は毎月マスの数字を直すだけ
6. あとは **入金・支払** を記録するだけ。実績・資金繰り・OKRの数字は自動で埋まります。

**迷ったら**：上帯の 📖（入力ガイド）に「どの画面に・何を・いつ入れるか」が4列の表で出ます。
🔔（ベル）には「いま手を打つべきこと」だけが出ます（期日超過・未消込・請求の作り忘れ・資金ショート）。

### 画面の並び（左メニューは8項目）
1つの仕事＝1項目。その中の「見方の違い」は画面の上の丸いタブです。

| メニュー | 中のタブ |
|---|---|
| ダッシュボード | — |
| 回収（売掛金） | 請求管理 ／ 入金・消込 ／ 未回収（年齢表） |
| 支払（買掛金） | 支払管理 ／ 支払実行 ／ 未払（年齢表） ／ 資金繰り |
| 取引先 | 一覧 ／ 台帳（履歴・タイムライン） |
| 費用・物件 | 月次費用表 ／ 物件（建物） ／ 分類別集計 |
| 予実管理 | 予実 ／ 期間比較 ／ 見込実績表 ／ 目標 OKR |
| 設定 | 勘定科目の登録 ／ 基本設定 ／ CRM連携 ／ ユーザー ／ API・AI連携 ／ 操作履歴 |

**未払（年齢表）**＝自社がまだ払っていないお金を、支払期日から何日過ぎたかで並べた表です
（**未回収（年齢表）**＝お客様からまだもらえていないお金の、裏返し）。

### 勘定科目は 大 › 中 › 小（もっと深くも）
**設定 › 勘定科目の登録** で階層を作ります。

```
販売費及び一般管理費          ← 大分類（ここで区分を決める）
├ 地代家賃                    ← 中分類
│  ├ 社宅・寮 家賃            ← 小分類（伝票で選べるのはここ）
│  ├ 事務所 家賃
│  └ 駐車場代
└ 水道光熱費
   ├ 電気代 ／ 水道代 ／ ガス代
```

- 区分（収益／売上原価／販管費／営業外）は **大分類でだけ**決め、下は受け継ぎます
- 伝票・費目で選べるのは **末端の科目だけ**。親も選べると親子で二重に数えてしまうため
- 使われている科目は消せません（「停止」にすると新しく選べなくなるだけ。過去の数字はそのまま）
- 「初期セット」は今の科目を4つの大分類にぶら下げるだけ。**コードも金額も変えません**

### 分類別集計 — 「A棟は電気でいくら？」に答える画面
**費用・物件 › 分類別集計**。行を押すと `大分類 → 中分類 → 小分類 → 建物` の順に開きます。
軸は **科目でまとめる ⇔ 建物でまとめる** を切り替えられます。
金額を押すと、その月にその科目・その建物で動いた **伝票そのもの**が出ます。

数字の出どころは予実と同じ伝票です。テストが2年度×4区分で1円単位に突き合わせているので、
予実と分類別で違う数字になることはありません。

### 物件（建物）— 借りている建物ごとのお金
社宅・寮・事務所・駐車場を1件ずつ登録し、**貸主・契約期間・家賃・共益費・駐車場代・敷金**を持たせます。
費用管理の費目に **物件** を選ぶと、家賃・電気・水道・ガスがその建物に集まり、
**物件 × 12か月**の表になります（行を押すと費目ごとの内訳）。
契約満了の **90日前** から画面と 🔔 で知らせます。更新・解約の連絡には時間が要るためです。

家賃の費目を **買掛** にしておくと、毎月の支払請求が自動で作られ、支払期日と残高でも追えます。

### デモデータ（設定 › 管理者のみ）
画面の動きを確かめるための作り物を、ボタン1つで入れられます。
取引先9社・物件4件・14か月ぶんの請求/入金/支払/費用など約350件。
会社ごとに払い方のくせを変えてあるので、取引先台帳のタイムラインの色が全部見られます。

- **勝手には入りません。** 管理者が押したときだけです（データが空でも絶対に自動生成しません）
- 入ったものは名前が `【デモ】` で始まり、内部に印が付きます
- 「全部消す」はその印の行だけを消します。**本物の請求・入金には触れません**（テストで確認しています）

### 取引先台帳 — 「この会社とは今どうなっているか」
会社を選ぶと、**履歴（通帳）** と **タイムライン（12か月の帯）** の2つで見られます。
一覧の取引先名をクリックすれば、どの画面からでもここに来られます。

- **履歴** … 請求と入金を1本の時間順に並べ、右端に残高。前期繰越つき。
  そのまま印刷すると **取引明細書・残高確認書** になります。
- **タイムライン** … 上3行が月ごとの請求計・入金計・月末残高、その下が伝票1枚ずつの帯。

帯の色は **その伝票の入金期日** と比べて決めています。**期日は取引先ごとに違う**ので、
「計上からの日数」では決して判断しません。20日締・翌々月25日払いの会社なら、
計上から85日かかっても **期日内（緑）** です。

| 色 | 意味 |
|---|---|
| 緑 | 期日内に入金（支払）された |
| 黄 | 30日までの遅れ |
| 赤 | 30日を超える遅れ・いま超過中 |
| 灰 | まだ期日が来ていない |
| 紫 | 過入金（過払い） |

取引先管理の **支払いぶり** の列に「期日内◯%・平均◯日遅れ」が出ます。
支払（買掛）側も同じ画面で見られ、そちらの色は **自社が期日を守れたか** を表します。

### 費用管理は「表1枚」です
領収書を1枚ずつ入れる台帳ではありません。正しい決算数値は会計事務所の試算表が優先です。
この画面の役目は **「毎月かかる費用が、いくらで、増えていないか」** を見ること。
月額予定から **10%以上ズレたマス** に色が付くので、値上げ・想定外の出費がその場で分かります。
金額は **税込**（実際に出ていく額）で入力し、予実には自動で **税抜** で入ります。
表の下に「うち消費税」の行があるので、税率が上がったときの負担も月ごとに追えます。

## デプロイ — push するだけ

VPS 側に **2分ごとに GitHub を見に行くタイマー** を入れてあります。`git push origin main` すれば、
2分以内に finance.biglight.jp が新しくなります。手で何かする必要はありません。

**最初の1回だけ**、VPS でこれを実行してタイマーを仕込みます：

```bash
ssh root@194.233.85.198
cd $(docker inspect yojitsu-web --format '{{index .Config.Labels "com.docker.compose.project.working_dir"}}')
git pull origin main
bash vps/autodeploy.sh          # ← タイマー登録 ＋ 溜まっている分を即デプロイ
```

| したいこと | コマンド（VPS上） |
|---|---|
| 動いているか見る | `systemctl list-timers yojitsu-autodeploy.timer` |
| ログを見る | `journalctl -u yojitsu-autodeploy -n 50 --no-pager` |
| 2分待たずに反映 | `/usr/local/bin/yojitsu-autodeploy.sh` |
| 止める | `systemctl disable --now yojitsu-autodeploy.timer` |

> **なぜ GitHub Actions を本命にしないのか**
> Actions から入るには VPS の秘密鍵を GitHub に預ける必要があり、鍵が漏れると VPS ごと取られます。
> タイマー方式は VPS が外へ `git fetch` するだけなので、外から入る穴を1つも開けません。
> `.github/workflows/deploy.yml` も置いてありますが、secrets（`VPS_HOST` / `VPS_USER` / `VPS_PORT` /
> `VPS_SSH_KEY`）を入れるまでは黙ってスキップします。

## 数字の約束（ここを間違えると全部ずれます）

| 事柄 | 決まり |
|---|---|
| 予実に効くのは | **計上月（bookMonth）**。入金日・支払日ではありません（発生主義） |
| 入金・支払は | P/L に影響しません。売掛金・買掛金の**残高が減る**だけ |
| 実績は | **保存しません**。請求書・支払請求・経費から毎回計算します |
| 予実の金額は | **税抜**。消費税は預り金であって儲けではないため |
| 確定した伝票は | **削除できません**（取消のみ）。金額変更は管理者・マネージャーのみ |
| CRMから来た項目は | 同期のたびに上書き。**締日・支払サイト・口座・請求ルールは絶対に触りません** |
| CRMで消えた会社・人は | 削除せず「CRM消失」の印だけ付けます（過去の請求書から辿れるように） |

## 安全装置（CRMの事故から持ち込んだもの）

- **全体書き込みAPIは存在しません。** レコード単位（`/state-delta`）のみ。
- **縮小ガード** — 1回の書き込みで件数が3割以上減るときは中止します。
- **バージョン履歴** — 書き込みのたびに全体のスナップショット。操作履歴から数秒で戻せます。
- **同期ログ** — ブロックされた書き込みも含め、誰が・どの端末から書いたかをDBに記録。
- **監査ログ** — どの項目が「いくら → いくら」に変わったかを日本語の項目名で表示。

## 外部API・AI連携（既定は停止）

外部システム（Power Automate など）と AI（ChatGPT）に、この システムの数字を**読ませる**ための口です。
**書き込みの口はありません** — 鍵を持っていても、AI でも、ここから金額は動きません。

| | |
|---|---|
| 開け方・止め方 | [`docs/API-MCP.md`](docs/API-MCP.md)（`.env` の `API_V1_ENABLED` / `MCP_ENABLED`） |
| 鍵の発行・失効 | 画面の **設定 › API・AI連携**（管理者のみ）。1人1鍵・発行時に1回だけ表示 |
| 外部API | `https://finance.biglight.jp/api/v1/…`（ヘッダー `X-API-Key`）・仕様書は `/api/v1/openapi.json` |
| AI（MCP） | `https://finance.biglight.jp/mcp`（OAuth。許可画面で鍵を1回貼るだけ。鍵はAIに渡りません） |
| よく使う答え | 未回収・債権年齢表・未払・予実・資金繰り・取引先ごとの残高 |
| 記録 | 読んだ分も断った分も 連携ログ（＝操作履歴）に残ります |

設計の根拠は [`CONG-THUC-XAY-DUNG-APP.md`](CONG-THUC-XAY-DUNG-APP.md) §17。
